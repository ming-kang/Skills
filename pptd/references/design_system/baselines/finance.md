# Finance Category Baseline

Category baseline for finance presets. The preset's signature system always overrides visual defaults below (background, palette, typography, layout/density) on conflict, never evidence boundaries. Each preset's `Density Baseline` sets per-slide minimums; impose no uniform module, data, or image quotas.

## Narrative Spine & IC Discipline
- **Spines**: Transaction decks follow `Executive Summary → Investment Highlights → Target/Market → Business Plan/Financial Diagnosis → Valuation & Returns → Risks & Mitigations → Decision Request`. Research/outlook decks follow `Core Stance → Evidence → Scenario Analysis → Allocation Recommendation`. Pass the title read-through test.
- **IC decision**: Each page answers one IC question; close with an explicit IC decision (approve, reject, approve with conditions) or allocation stance (overweight, underweight, range) plus actions and timeline—never a thank-you slide.
- **Titles/evidence**: Body titles are investment assertions with a one-line scope/reading subtitle. Run parallel evidence in 2–3 columns of numbered claims (bold assertion + short proof).

## Tables, Valuation & Risk Semantics
- **Model tables**: High-density financial tables (three statements, comps, scenarios, sensitivity) carry the argument, separating assumption columns, driver rows, and check rows. Column/right-align numbers with consistent thousands separators and negative-number conventions deck-wide.
- **Traceability**: Set key metrics larger than body text beside unit, as-of date, and basis. Label estimates illustrative/internal; no unsourced numbers in the main area. Put source, basis, and date range in small gray footer text on every page.
- **Scenarios/anchors/assumptions**: Present returns only as scenario ranges (bear/base/bull with probabilities or drivers), never a single-point IRR; pair valuation conclusions with sensitivity tables. Anchor valuations with comps, precedent transactions, or DCF cross-checks. Box explicit assumptions on dependent pages.
- **Risks/charts**: Pair risks with mitigations (`Risk → Probability/Impact → Mitigation → Owner/Status`). Distinguish actuals from forecasts (dashes, light tints, hatched bands) with labeled basis. Label marks and bridge blocks directly, name drivers in-chart, and avoid 3D, shadows, or gradient fills.

## Visual Defaults & Prohibitions (Overridable)
- Compliance-clean: no lifestyle photos, decorative icons, marketing superlatives, watermarks, or confidentiality stamps.
- Choose one temperament per deck (dark navy/charcoal + metallic, or white + blue-gray); serif titles allowed for gravitas, sans-serif for tables/labels/numerals; lock one red-green positive/negative pair for financial meaning only.
- Inherit [slides_categories.md](../../slides_categories.md): no default cards (functional boxes exempt), no unjustified equal splits, no empty planned regions.
